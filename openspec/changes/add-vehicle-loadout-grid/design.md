# Design

## Context

物理核心已是无 DOM 的函数式模块，profile 为纯数据。装配模型沿用同一风格：纯数据 + 纯函数 + 可单测。

## Decisions

- **车体局部坐标**：格子以车体中心为原点、车头为 +x，单位为"格"，格边长作为全局常量，后续质心计算以此换算米。
- **双层独立**：内外层各自一个占用图，互不检查重叠，但外层受底盘外轮廓约束。
- **数据驱动**：底盘与部件定义放在 TS 数据表，装配清单仅存 ID、锚点格、旋转，不复制定义，便于版本升级。
- **操作返回新状态**：放置/移动/旋转/移除均为纯函数，返回新装配或错误，便于撤销与 UI 预览。
- **外挂部件**：用部件标志 `exposed` 表达，不另设第三层。

## Risks / Trade-offs

- 格子尺寸与物理尺寸的换算需在 `add-assembly-physics` 中固定，本变更只暴露格坐标。
- 形状允许任意 polyomino 会增加 UI 难度；首版限制为预设形状集。

## Implementation Contract

- 以 `docs/GAME_VISION.md` 的空间构筑为约束；本变更提供共享数据合同，工作台由 `add-vehicle-ui` 消费。
- 格边长固定为 0.12 game-L，质量字段使用 kg；后续 compose 按 1000 kg = 1 game-M 换算，避免将当前核心游戏单位误称为米。车头 +x，右侧 +y，整数格坐标的中心即格中心。
- 十车型的内层采用按物理车长/车宽向下取整的奇数矩形（最少 7×3），外层在四边各增加一格。中心外层为 roof 槽，边缘为 edge 槽；内层为 internal 槽。格子仍显式保存 available 和外露方向，允许未来非矩形底盘。
- 清单版本为 `vehicle-loadout-1`；只保存 chassisId、稳定 instanceId、partId、layer、整数锚点、四分之一圈形状旋转以及八方向 facing。形状绕锚点旋转，不自动平移。facing 与形状旋转独立，解决多格武器转向不应改变占地的问题。
- 部件定义包含层、槽集合、形状、允许旋转、最大数量、质量、耐久、标签、外露、供电、弹药及动力链描述。定义表仅含占位平衡值；不得将定义数据复制到序列化清单。
- 摆放、移动、旋转、朝向修改和移除统一验证完整候选装配。失败返回错误代码、实例/定义 ID 与冲突格，并保留原对象；成功返回新对象。加载时同时拒绝非整数/非有限坐标、重复实例、非法旋转/朝向、未知字段和非法布局。
- 每个车型提供可重建的固定 ID 出厂清单，包含驾驶座、发动机、变速箱、油箱、电池、武器；以确定性首个合法位置放置。预设每次返回独立副本，恢复不受玩家编辑污染。
- 能源、弹药为整车共享预算：汇总电池容量/输出/充电、耗电、弹药与油量，不要求格子连线；运行时消耗属于后续武器/副本模块。
- 稳定序列化按 instanceId 的代码点顺序排序并固定字段顺序；往返时重新执行全部校验，禁止静默修补。

## Verification

每个数据与操作任务同时提供单元测试；覆盖十车型几何/预设、跨层独立、错误原子性、槽与可用性、数量上限、旋转、八向挂点、恶意清单与稳定往返。文档说明坐标、版本和全局资源接口；最后运行类型检查、装配测试和 OpenSpec 严格校验。
