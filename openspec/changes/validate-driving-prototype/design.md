# Design

## Context

v2控制器接收期望，物理只接收执行器；详见build-vehicle-physics/design.md。v1接入完成状态仅是历史。

## Goals / Non-Goals

保持现有单指输入、固定方向镜头和竖屏布局；交付v2真实接触与反馈。不增加冒险或解锁系统。

## Decisions

无碰撞场景严格复用核心步进；碰撞用车身矩形接触点冲量及扫掠，不能按摇杆重设速度或清横摆。UI区分目标速度、动力输出、漂移请求和实际侧滑；胎痕按各轴实际滑移。快照保存完整profile、时间及控制/物理历史。新证据写vehicle-physics-2，历史不覆盖。

## Integration Contract

- `stepInWorld`按1/120秒调用同一核心；无接触时严格返回核心结果。车身使用轴距、宽度、前后悬生成的OBB，SAT和多边形裁剪给出接触法向/作用点；按平移长度加端部转动距离采样，二分接触时刻，法向无弹性冲量和0.25接触摩擦改变平移与横摆。
- 快照固定为vehicle-snapshot-2，保存有效参数完整副本、模拟时间、轮速、力、加速度、控制历史和能量。恢复拒绝缺失字段及旧版本，不按ID重新加载默认参数；时间相关路面和同ID改参须能精确续算。
- 前后轴胎痕分别使用组合滑速及摩擦功，覆盖纯旋转和动力空转；使用同一四轮几何。验证面板显示执行器请求、包络、饱和、轮速和能量，普通页面采用目标速度和漂移辅助文案。
- 浏览器覆盖320×568、360×640、390×844、完整触控生命周期与十车型。碰撞回归检查车身不穿透、能量损失和旋转保留，不再要求撞击后全车归零。真实手机驾驶仍作为独立未完成任务。

## Risks / Trade-offs

长车接触和强旋转需要独立测试；纯核心通过不代表网页或手机通过。真实手机无法由桌面自动化代替。

## Migration Plan

先接核心、快照与接触，再改观测/说明，执行单元、浏览器、回放和构建；人工手机项单独保留。
