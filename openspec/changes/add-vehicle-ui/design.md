# Design

## Context

见 proposal.md。装配、派生、武器视觉、部件耐久和档案事务已有纯逻辑接口，工作台消费它们。副本通过准备页进入，练习场保持独立。

## Goals / Non-Goals

**Goals:** 一个真实库存支持的双层工作台和不妨碍驾驶的战斗 HUD；鼠标、触摸及键盘按钮均有可行操作路径。

**Non-Goals:** 本期不替换 Canvas 2D、不增加开火/瞄准控件，不新增云存档或正式美术资源。

## Decisions

- 使用原生 dialog、等边绝对定位网格和 Pointer Events；相比引入 UI 框架可复用当前小型客户端。格子行按 x 逆序显示车头向上、列按 y 排列；所有编辑调用 loadout 核心，不复制碰撞与槽规则。
- 指针捕获后通过网格矩形和正方格坐标定位落点；拖动阈值 5px，保留点击库存→点击格子的替代路径。取消拖拽不写入；旋转/朝向/卸下按钮操作选中实例。
- 未选层以半透明、不可点击覆盖显示，活跃层格子携带坐标与部件名；边缘槽单独标记。性能看板直接消费 moduleComposition，反映持久耐久与等级。
- 工作台可由营地装备区或准备页打开，使用装配需事务保存；方案引用缺失明示，出厂预设只重排库存。升级、维修、购买和解锁事务成功后再更新 UI，失败保留原值。
- 纸娃娃以原始装配作位置基准、当前模块状态作颜色；外露脱落保留叉号及缺口，附状态文本。HUD 左下限制宽高，主视口中心不放模块提示。
- 武器渲染在世界地面层执行，以车体为中心用 evenodd 裁切剔除净空圆；射界、准星、装填弧、热量弧全部在同一裁切内。中心按当前插值位置更新，保守增加一逻辑步移动余量，保证动态净空。
- 伤害显示按目标、种类和 0.2 秒时间窗聚合，限制 24 条且过期回收；仅呈现层聚合，不改变真实伤害事件。
- 结算保存失败留在结算页，提供重试；成功前禁用下一局。浏览器场景测试覆盖布局、非法拖拽、方案持久化、纸娃娃与 Canvas 净空。

## Vehicle View Refinement

- 内外层共用外层包围网格作为显示坐标，CSS 单一 cell-size 同时控制行高与列宽，所有可交互格保持正方形。
- 原生 SVG 绘制同一车型的外观/底盘：车轮、翼子板、车头、玻璃或纵梁/横梁可辨认。网格叠加在车辆结构上。
- 部件根据 occupiedCells 生成联合边界，SVG 内不绘制内部格线；每个实例一个整体命中区和标签，支持不规则轮廓及旋转。另一层以完整装备的半透明轮廓显示。
- 拖拽保留抓取点相对锚点的格偏移，点击装备和网格均回到相同核心编辑接口。

## Combat Presentation Revision

Canvas 增加车辆绘制后的实体层，武器本体按插值车辆位置及实际炮口角绘制；射界指向细线留在地面提示层并保持净空裁切。独立 CombatEffects 消费带序号/时间的事件，限制容量并按模拟时间回收，双方共享弹丸和命中样式，角色外形依据敌人类型绘制。原生矢量数据复用于装配视图。

## Durability Feedback Refinement

- 驾驶校验分别说明必需部件未安装与已安装但零耐久毁坏；工作台直接复用模块损伤阈值，以耐久、文字和图上红叉呈现失效。维修仍使用原档案事务与费用。关闭工作台时重新读取已保存的耐久/等级，准备页重建当前装配预览，未保存的布局不生效。

## Risks / Trade-offs

- 小屏格子过密 → 工作台局部滚动、最小格尺寸及点击替代拖拽。
- 多武器射界可能杂乱 → 低透明度地面扇形、净空裁切、外沿状态和聚合显示。
- 手机手感与性能尚无真机条件 → 保留既有两项真机待办，浏览器竖屏验证不替代真机。
