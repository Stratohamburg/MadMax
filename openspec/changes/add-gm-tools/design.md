# Design

## Context

见 proposal.md。newProfile 已用目录最大耐久创建出厂预设，预设含机枪和弹药箱；营地渲染器尚未调用武器本体绘制。档案通过 IndexedDB 事务保存主档、备份和 pending 结算，正常 update 会拒绝待处理结算。

## Goals / Non-Goals

**Goals:** 复用原有目录、预设和校验保证调试数据可正常进入装备和战斗；写入成功后才刷新运行态。

**Non-Goals:** 本期不增加服务器管理、远程发奖或账号权限，GM 是当前本地原型功能。

## Decisions

- 新增独立 GM 纯数据操作，校验数量及安全整数总额，生成唯一零件实例；复用 repository.update，避免界面直接改 IndexedDB 或绕过档案格式校验。单次数量上限：货币/废料 1000000，零件 100。
- reset 使用独立事务直接创建 newProfile，以同一新档同时覆盖 primary/backup，移除 pending，避免普通 update 保留旧备份导致重置后进度复活。
- GM 使用原生 dialog，入口放营地顶部，复用营地的暂停、清输入和关闭刷新流程。提交期间禁用操作和关闭，reset 以勾选明确清空说明后再点击按钮确认，成功后重新进入营地。
- 采用库存全修复帮助恢复现有进度；正常启动保留战斗损伤，显式重置才重建完整初始车辆。
- 营地前景通过已有武器设计绘制挂载，使用插值后的车辆位置、角度及质心相对挂点，避免静态装饰机枪与真实装配不一致。

## Risks / Trade-offs

- 数量过大造成卡顿 → 发零件数量限制为 100，资源限制单次 1000000，总值保持安全整数。
- 误触丢失进度 → 明确清除范围、默认禁用重置按钮，要求勾选确认。
- 写入失败导致 UI 与档案不一致 → 原子提交成功后才替换内存与跳转，失败提示并允许重试。
- GM 影响游戏经济 → 当前按用户要求在本地原型直接提供，未来联网版本须重新设计授权边界。
