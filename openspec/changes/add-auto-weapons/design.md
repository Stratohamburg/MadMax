# Design

## Context

战斗需与固定步长物理同步，且需支持数百弹丸的"天女散花"场景。武器逻辑应与渲染分离并确定性运行。

## Decisions

- **触发策略接口**：每种武器类型实现 `canFire(context) -> FireDecision`，四类触发（炮台/固定/制导/被动）各为一种策略，由数据中的 `trigger` 字段选择，新增类型不改核心循环。
- **世界/局部变换**：挂点与朝向取自装配清单，每步用车体位姿换算到世界坐标。
- **目标查询**：通过空间哈希提供射程/扇形查询；查询接口在 `add-combat-damage` 中提供，本变更定义接口并用测试替身验证。
- **制导进度**：每武器单独维护进度计时器，状态可序列化以便回放。
- **确定性**：不使用 `Math.random`，随机散布使用可播种 PRNG，种子进入战斗状态。
- **后坐力**：开火产生外力事件，由 `add-assembly-physics` 的外力接口消费。

## Risks / Trade-offs

- 弹丸数量大时的开销在 `add-combat-damage` 中以对象池处理；本变更只产出开火事件。
- 目标选择规则过多会增加平衡难度，首版提供 3 种规则。

## Open Questions

- 被动触发事件的完整列表需随 `add-roguelike-modifiers` 的标签体系一起确定。
