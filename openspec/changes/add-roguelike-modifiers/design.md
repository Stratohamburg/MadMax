# Design

## Context

后期爽感来自倍率叠加，同时数值易失控。分层规则需在一处实现并由车辆、武器、伤害共用。

## Decisions

- **单一属性求值器**：`evaluate(base, modifiers, tagContext)`，被 compose、武器和伤害管线调用。
- **标签集合**：目标自带标签集合，修饰符以"全含/任一"匹配；标签表集中维护。
- **协同**：基于同层占格的四邻接图预计算。当前网格较小，装配变化时线性重建并由会话缓存，不在每个模拟步重算，避免维护增量缓存的失效风险。
- **候选生成**：加权无放回抽样，权重 = 基础权重 × 稀有度系数 × build 标签倾向；保底计数器随局内状态保存，使用可播种 PRNG。
- **诊断工具**：无头 CLI，输入装配+加成，输出属性贡献表与估算 DPS，用于数值平衡与回归。
- **局内范围**：加成状态属于一局，随局结束丢弃；仅结算时的掉落进入局外。

## Risks / Trade-offs

- 乘算层过多会爆炸：设置乘算来源分组（同组乘算合并）并提供诊断阈值。
- 标签设计需与内容同步演进，首版限制标签数量。

## Implementation Contract

- 复用 `src/stats/modifiers.ts`；支持 vehicle/weapon/damage 目标、来源分组和可选实例作用域，堆叠生成稳定修饰符 ID，同一来源内按层累积，乘算保留来源贡献。
- 相邻限定同层且占格四邻接；同类弹幕/爆炸/火焰武器各获得每邻居+10%伤害，通过 instanceId 只作用于相邻实例，分开后消失。
- 升级表采用 common/rare/epic，稀有度权重系数 1/0.35/0.08；同 build 标签候选权重×3，三选一加权无放回。连续3次无匹配标签后下一次至少一个匹配项；无可匹配项时返回可用项并标记无保底候选。
- 已达上限的卡片不得进入候选；不足3种则返回实际可选数量，无候选时返回空列表并明确耗尽。局内初始可刷新3次，刷新计入播种状态；待选项存在时重复请求不重抽。
- 限时项支持 replace/extend 刷新；堆叠不超上限，已有项可由事件直接刷新持续时间。时间以固定步累积，到期移除；新 run 必须重新创建空升级状态。
- CLI 接受装配文件与升级 ID 或使用固定示例，输出 profile、每武器伤害/射速/弹数贡献、爆发/考虑热量的估计DPS；乘算积>8、乘算来源>8或物理参数截断时给出告警。
- 诊断不是实战命中率/移动设备性能承诺；共享求值、候选、相邻与期限由逻辑测试验证，UI 在副本/车辆界面消费该状态。
