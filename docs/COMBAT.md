# 战斗、损伤与维修

`CombatWorld` 以 1/120 秒固定步推进。实体和弹丸采用 typed arrays 固定容量池，空间哈希复用桶；实体死亡只发一次事件，之后从索敌与碰撞中移除。当前敌人以配置武器进行远程攻击，机动单位按有限加速度追击并在攻击距离停下；建筑固定。核心仍支持具有0.75秒冷却的接触攻击，当前远程敌人配置的接触攻击伤害为0。

## 碾压与撞击

玩家与敌方车辆、敌车之间使用真实车身 OBB 接触，交换双方线动量与横摆；步兵和建筑使用车身矩形与实体圆形接触。仅保守包围圆重叠不造成撞击伤害。场景扫掠、接触求解、摩擦和恢复系数均在物理模块内执行。玩家撞击每个目标的伤害冷却0.5秒，冷却期间物理接触仍连续处理。

敌方 AI 仅提供目标方向、速度与驾驶请求，复用玩家的控制、机械、轮胎及资源推进。碰撞和武器后坐力更新现有车辆物理状态，不重建燃料、电量、挡位、控制历史和喷射冷却；武器使用实际挂点及本步剩余输出，敌车状态和冲量去重历史纳入世界快照。

步兵在法向接近速度达到1.2游戏长度/秒且产生正冲量时被撞死；慢速擦碰不会触发秒杀。碾压同时对车体造成至少3、至多15点的冲量派生物理伤害，绕过外挂吸收后再受车体护甲减免，避免撞人不扣血。车辆/建筑按接触冲量计算伤害，建筑不会被推动。死亡、击杀、经验和伤害进入正常结算与幂等存档，不重复发奖。

## 双方战斗反馈

展示事件带递增序号、模拟时间、阵营、武器和世界位置。世界保留最多512条；`CombatEffects` 去重后最多绘制256个短时特效，按模拟时间回收。命中点取扫掠实际入射位置，爆炸在真实爆点出现；角色死亡分别显示火星或爆炸。展示和伤害事件分开消费，绘制不会推进模拟或改变随机序列。高负载时展示容量会限制可见粒子数量，伤害结算仍独立进行。

## 伤害与弹道

伤害顺序为共享 flat/increased/more → 暴击 → 抗性 → 护甲。抗性限制为 0～0.9，护甲倍率为 100/(100+armor)，最终伤害不小于零。`calculateDamage` 返回每层贡献，武器事件在生成弹丸时固定进攻侧倍率与暴击，命中时应用目标防御。

高速弹丸按每步位移线段扫掠。穿透记录已命中实体，避免同一弹丸跨步重复命中；爆炸对每个范围目标一次结算，不叠加直击。制导受有限转速限制，目标丢失后直飞。燃烧按来源刷新持续时间，最多8个来源，固定步结算。

扫掠按圆形目标的实际入射点排序。满池合并穿透弹时，为每个目标保留已结算伤害额度；后续合并仅补结新增载荷，既不因旧命中集合吞掉新增伤害，也不重复应用旧伤害。

默认最多2048弹丸、128敌人及一个玩家槽。弹丸容量最少6，包含阵营×伤害类型的6个保留槽。普通槽耗尽后使用本组保留槽，继续溢出时将同阵营同伤害类型载荷并入最近弹丸，累加伤害和数量；`aggregated` 与 `emittedDamage` 记录聚合与载荷账本。聚合近似轨迹和命中时间，因此高负载时视觉/目标分配可能变化；同类型累计伤害载荷不丢弃。敌人满池时刷新方保留待刷新项。

## 模块与驾驶

耐久 >50% 为 Normal，0<耐久≤50% 为 Damaged，归零为 Destroyed。装配健康比例由 `moduleComposition` 传给 compose：发动机受损功率减半、变速箱换挡时间加倍、电池最大输出减半；武器层处理射速减半与散布加倍。

`damageByDirection` 根据挂点朝向选择覆盖方向的外层件，再到内装甲，余量作用于车体并损伤内部件。外露部件毁坏后脱落、质量与功能移除；内部毁坏件保留质量。油箱毁坏记录起火事件，电池毁坏移除供电。`damageModule` 可以供精确部件命中使用。

弹药箱毁坏后移除其可用容量；副本同步截断剩余弹药、电量和燃料至当前有效容量。模块与升级变化时重算装配和邻接修饰符，普通步复用缓存。

机械师占用内层格并缓慢修复非零耐久件，不能复活 Destroyed。维修区快速修复；仍安装的零耐久件先恢复到50%，下一步才继续维修。`serviceVehicle` 同时按当前装配容量补满弹药。已脱落部件不在装配中，维修不会凭空生成。

## 压测与设备边界

```powershell
npm run combat:benchmark
npx vitest run tests/unit/combat.test.ts
```

浏览器/手机打开 `/?combat-benchmark=1` 点击压测按钮。预热120步，测量600步，记录实际峰值弹丸数、敌人数、p50/p95/max单步耗时及聚合数量。工程目标为2048/128、p95≤4ms；结果的 `mobileVerified=false` 不会因 UA 看似移动设备而自动修改。

本机结果保存在 `openspec/changes/add-combat-damage/evidence/desktop-benchmark.json`。真机验收还需设备型号、系统、浏览器版本、热机时长和测试报告；用户于2026-11-01确认当前无法连接手机，因此此任务保持未完成，其余工作继续。

新增真实敌方武器压力记录为 `desktop-roster-benchmark.json`，可用 `node --import ./scripts/physics-loader.mjs scripts/combat-roster-benchmark.ts` 复现。128个敌人覆盖全部七种配置，2048弹丸满池，预热120步后测量600步，同时消费展示事件：本机p50为1.6175ms、p95为2.8166ms、max为6.0150ms，敌方实际发射1564次；事件/可见特效分别封顶512/256。该记录只测固定步模拟和事件消费，不含Canvas绘制及预填弹丸开销；`mobileVerified:false`。

上面的 roster 报告对应旧敌车运动方式，仅保留为历史。v5 重新测量完整共用车辆物理：128 个敌人中 54 辆车，2048 弹丸容量，预热 120 步、测量 600 步；本机 p50=11.3302ms、p95=14.7717ms、max=18.0040ms，实际发射 1491 次。已减少重复车型复制、实体查找和不可变状态构造，仍未达到 p95≤4ms 目标，满负载下也超过 120Hz 的单步时间预算。当前报告明确记录 `withinEngineeringTarget:false`，保存于 `add-assembly-physics/evidence/vehicle-physics-5/desktop-roster-benchmark.json`。下一阶段需优化批量车辆求解和接触候选管理；不能用历史报告或缩减物理行为宣称已满足预算。

复现 v5 报告且保留历史文件：`node --import ./scripts/physics-loader.mjs scripts/combat-roster-benchmark.ts openspec/changes/add-assembly-physics/evidence/vehicle-physics-5`。
