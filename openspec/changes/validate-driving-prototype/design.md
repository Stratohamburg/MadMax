# Design

## Context

本变更转为车辆物理的移动端接入与驾驶验证。唯一物理行为来源为 [vehicle-physics spec](../build-vehicle-physics/specs/vehicle-physics/spec.md)，公式、参数分组、十车型配方、研究取舍与数值验收见其 [设计](../build-vehicle-physics/design.md)。旧轴动力规划由该独立变更取代，不在本文件保留第二套物理。

当前baseline-1客户端已有输入、固定时钟、练习场和自动化测试，原手机验收未完成。轮位在render／trails中分散，碰撞为质心圆，主循环及测试允许独立改speed／motion，均需迁移。

## Goals / Non-Goals

**Goals:**

- 将现有零死区摇杆与固定时钟接到核心公共合同，所有消费者读取一致状态。
- 路线方向输入、实际前轮、侧滑／反打及长车占地在手机界面可观察。
- 验证模式可选择十类配置并比较三类路面，保留单辆活跃车与明确重置。
- 核心与接入验收分开记录，保留历史，完成本变更自己的浏览器与手机检查。

**Non-Goals:**

- 不在scene或main重新实现轮胎、横摆、漂移控制与车型算法。
- 不实现车辆解锁、库存、载货、拖挂、战斗或正式美术。

## Decisions

### 1. 职责与单向依赖

| 责任 | 所属变更 |
| --- | --- |
| 状态、参数、几何、载荷、轮胎、积分、辅助、十车型及纯物理基准 | build-vehicle-physics |
| Pointer Events、输入分区、时钟驱动、后台清理 | validate-driving-prototype |
| 车型选择／调参、三路面练习区域、相机、轮胎画面与胎痕 | validate-driving-prototype |
| 长车占地扫掠、静态接触反馈、碰撞后调用核心停车 | validate-driving-prototype |
| 核心数值／受力／差异报告 | build-vehicle-physics证据 |
| 触控／场景／碰撞／浏览器／真机 | 本变更证据，引用准确核心版本 |

核心不得导入scene／DOM，场景向核心提供轴接地点的路面采样。核心公共接口可先独立实施和验收；本变更依赖可消费版本，无需等核心归档才编码，但整体验收须记录已通过的准确核心版本。

### 2. 输入与参数边界

任意非零摇杆位移输出targetSpeed=当前车型Vmax*min(r/R,1)和世界路线角chiTarget。方向始终为路线，漂移不换含义；直接传入核心，不能先改heading再调用。精确回中／取消时目标速度零、方向null、漂移false。

R、Rexit、Renter与触控生命周期属于独立输入配置，所有车型共享，不放进物理车型参数。主视图保持至少60%，三视口与安全区合同不变。漂移布尔值即时反馈，核心h和侧滑参考连续变化，界面不把h滞后错误当成输入仍未退出。

### 3. 生产切换与完整状态

先由核心变更提供可独立测试的新模块，当前baseline客户端可作为尚未切换的历史入口运行。接入时一次性替换公共model门面与消费者，移除旧heading／motion追赶算法；任一运行实例只有一套权威状态，不能让新配置走旧模型或让标量speed覆盖速度向量。

重置／换车／应用配置使用核心一致初态，额外清活跃输入、时钟积压、镜头、绘制插值和胎痕。换车从出生点进行，不在行驶中热换m、Iz或轮位。旧触点不接管。碰撞调用核心停车，清平移、r及会释放旧作用的轮胎历史；完全阻挡撤回本步车身姿态，前轮允许打方向。

页面隐藏冻结物理、清输入和积压；恢复不补算后台、不追旧路线，下一前台步按零输入减速稳定。快照记录modelVersion、profileSchemaVersion、profileId／revision、路面与场景版本，测试初态统一构造。

### 4. 车型选择与观测

普通界面保持速度／漂移／重置等驾驶信息；验证模式提供十车型选择、配置修订、恢复默认及成组参数编辑。非法版本或组合明确拒绝且保留当前配置；合法应用后完整重置。

验证观测直接读取核心：chiTarget、theta、chi、beta／betaTarget、实际／目标前轮、r、h、低速混合、轴载荷、侧偏／轮胎力／预算、前后路面、动力／阻力／物理／游戏代价和保护。可以展示F/m、Iz/(mL²)等派生值，但普通玩家流程不加入实现细节。

### 5. 绘制、胎痕与长车占地

四轮、车身边界与胎痕使用核心几何；前轮读取实际等效角／阿克曼派生显示角，后轮沿车身，不以动画假装反打。姿态最短弧插值，渲染不推进物理。镜头固定世界方向，可调整统一可视尺度保证重卡及前方路线可辨，不改变屏幕输入含义。

胎痕基于接地点滑速、侧偏或耗散，正常低速几何betaKin不触发；退出漂移后实际滑动仍可留痕，保留6秒寿命及1600段容量上限。

原圆形碰撞不足以覆盖长车。接入使用按车长／车宽／前后悬生成的保守足迹，可采用覆盖车身的胶囊／圆链或有向凸形扫掠，但必须验证包住声明占地，并处理平移与旋转扫掠，不能只检查质心或本步终态。首版保持静态障碍、不反弹、不伤害；相接存在可通行切向空间时可以起步脱离。实现选择以扫掠和旋转测试通过为准，无需通用刚体引擎。

### 6. 验证场、路面和场景

保留直道、缓弯、急弯、连续弯与静态障碍，新增或标明开放几何圆、普通对齐、持续漂移／反打及干硬路／松散地／湿滑地比较区域。只驾驶一辆当前车型；切换后重置，离线报告可比较多车，无需同屏十车。

固定前轮／纯运动学入口仅验证模式可用，调用核心场景而非改玩家输入。普通对齐和反打定义、各车型时间包络与持续侧滑门槛全部引用独立物理设计，不在本文件另定门槛；场景需远离碰撞，只有碰撞专项才启障碍。十车型至少完整接入检查，真实手机重点覆盖默认跑车、重卡及拉力车。

### 7. 证据与验证

核心证据由build-vehicle-physics保存；本变更新证据写evidence/vehicle-physics-1/<profileId>/<profileRevision>/，包含核心版本及场景版本，不覆盖baseline-1文件。acceptance.md实施时追加新章节，旧记录只作历史。

本变更验证三视口、原输入合同、每车速度映射与切换、前轮显示／反打、接地点胎痕、三路面、长车最高速度／转向扫掠碰撞、完整重置／后台、场景链路10秒30/60/120FPS回放及至少一台真机。回放容差沿用核心规范，不能把核心报告替代浏览器交互，也不能以截图替代驾驶。

## Risks / Trade-offs

- [边界拆分后重复实施] → 物理公式和配置仅在独立spec，原2.6～2.10核心任务迁走，本清单保留消费适配。
- [车型换了但输入还用旧Vmax] → 每次重置绑定当前profile，浏览器检查各车R/2与R映射。
- [长车头尾穿墙或原地转动] → 足迹包络、旋转扫掠、完全阻挡撤姿态与核心清历史共同测试。
- [调参使物理差异被面板错误覆盖] → 完整配置校验、版本快照、应用后重置，不局部写权威派生值。
- [历史通过被误读成新版通过] → 新版单独记录，手机未做保持未完成。

## Migration Plan

1. 保留现有baseline-1验收和证据，核心按独立变更提供公共接口与预设。
2. 接输入／状态／版本及生命周期，再迁移几何、画面、路面采样、足迹碰撞与面板；一次性切换生产模型。
3. 建场景证据，复跑三视口和十车型的接入回归，更新README、总览、操作与验证说明的路线语义和spec入口。
4. 至少一台真机评估跑车、重卡、拉力的前轮、持续漂移、反打和误触；调校回到核心版本管理，再复跑受影响项。
5. 若失败，成套回退核心／配置／消费者组合；不能只回退一个物理文件。两个变更满足各自验收后分别归档。

- 车型面板的具体排版和三路面区域位置按三视口可读性选择，不改变合同。
- 实机设备和浏览器由可用条件决定，执行前记录，不把缺少实机改成通过。
