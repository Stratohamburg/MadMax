# 本地档案

副本入口自动打开 IndexedDB `madmax-profile`。schema 2 保存实例库存（等级/耐久）、多套命名装配、货币/废料、底盘/部件/关卡解锁、主线、统计和已入档 runId。新档为跑车初始装配、250 货币、100 废料。

初始装配的每个部件均按目录最大耐久创建，包含车顶中央机枪及弹药箱。营地 GM 发放与全修复复用档案更新事务；显式重置使用独立事务同时替换主档和备份并清除 pending，恢复完整初始状态，失败时原记录不变。详见 [GM 调试工具](GM.md)。

规范化 JSON 加 FNV-1a 校验检测意外损坏。主档、上一有效备份、待入档结算在一个记录里，更新使用单个 readwrite 事务。终局先写 pending 再入档；重启恢复 pending，重复 runId 不再发奖。多标签页写入串行。校验失败恢复备份并提示，双坏阻止覆盖；未来版本直接拒绝并保留原记录。schema 1 显式迁移补齐等级/耐久和 runId 集合，样本在 `tests/fixtures/profile-v1.json`。

出厂布局只匹配已有实例，蓝图丢失引用会列出缺失项；还原预设不赠送零件。购买 50 货币/10 废料，内容解锁 100/20，升级至新等级 L 消耗 50L/10L，上限 5。武器伤害/发动机动力每级 +5%，维修 20/5。结算耐久参与下次出击。

`ProfileRepository` 接受 `AtomicStore`；浏览器使用 IndexedDbStore，测试使用可注入中断的 MemoryStore。升级/维修/购买/方案变更只在事务成功后更新页面档案。资源不足不修改原档。浏览器清除站点数据会删除档案，首版没有云同步。

验证：`npx vitest run tests/unit/persistence.test.ts`，覆盖迁移、未来版本、校验回退、中断重启、并发重复入档与真实库存引用。
