# Design

## Context

装配负责把底盘、部件、健康和加成转换为核心参数。机械行为的唯一合同见 build-vehicle-physics/specs/vehicle-physics/spec.md；历史 v3 实施记录保留在 acceptance 与 evidence。

## Decisions

- compose 是无 DOM、无随机、无运行时积分的纯函数，依赖核心发动机/变速箱/助推参数类型，不反向让核心依赖装配。
- 使用 0.12 game-L 格和 1000 kg = 1 game-M，部件取占格中心点质量；质量加权质心和平行轴惯量不得截断。对核心不支持的质量几何明确报错；可调轮胎性能仍可有限截断并在摘要显示。
- 支持域内质心始终同时用于 profile、轮廓、挂点和摘要。核心保留 v2 空装配数值基线；出厂装配、重装配与偏心装配另做稳定性验收。
- 共享属性层 flat→increased→more。power 属性修改发动机有效扭矩和功率，随后由核心限制变速箱承载；不在最终轮端力上附加绕过限幅的倍率。
- 健康决定部件有效参数与可用性：发动机半功率/扭矩、变速箱双倍换挡时间、内部毁坏仍有质量、外挂移除。驾驶权限、动力、转向、制动和助推分开，不用 canDrive 总开关冻结前轮。
- AssemblyDrive 只编排当前可用机械能力→驾驶请求→机械执行器→刚体积分，燃油、电池和请求归此接入层；机械积分统一调用核心。自动助推请求保持高目标速度和路线对齐策略。
- 损伤、脱落、升级与营地改装统一走核心质量迁移。燃油、电量和冷却保留；容量减少取小，增加不自动补满。更换变速箱只校正失效挡位，禁止顺带重置刚体或控制历史。

## Risks / Trade-offs

- 支持域外装配明确错误可能暴露工作台边界 → 在现有错误区展示原因，不输出伪造参数。
- 出厂参数与装配后的质量不同 → 单独验收普通急转、快速换向与偏心重装配，碰撞及既有失稳允许 spin。
- 扭矩和功率使用游戏单位标定 → 仍提供机械诊断与单位，不宣称真实发动机、离合或悬挂还原。

## Verification

验证核心独立动力链、加成后限幅、换挡连续、断油转向；检查支持域边界、质量/质心/惯量/挂点一致；旋转脱落与资源不补满；十车型真实装配三路面低中高速度急转/换向，以及重装配和偏心装配。旧 v2/v3 证据不修改，v4 验证记录另存。
