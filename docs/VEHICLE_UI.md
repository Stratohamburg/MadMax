# 车库与战斗反馈

在默认营地 `/` 开到出生点正前方的装备停车区，松开摇杆并停稳 0.7 秒，进入“装配工作台”；也可从 `/?mode=pve` 准备页进入。上方“底盘俯视 / 外观俯视”切换车辆底盘结构和完整车身外观，包含车头、四轮、车窗或底盘纵横梁，透视可显示另一层的完整部件。

内外层共用同一坐标，车头朝上，所有格子严格等宽等高，虚线为外沿槽。发动机、变速箱等多格装备各自绘制为一体轮廓，内部没有格线。点击任意可见部分选中同一实例；拖动时保留抓取格与锚点的偏移。部件从仓库拖入，或先点击仓库再点击格子；旋转改变占格和外形，朝向以 45° 改变武器朝向，二者独立。非法摆放显示核心原因并保留原布局。

看板实时更新质量、质心、轴荷、动力、极速、抓地、供电、燃料和弹药。耐久和升级等级参与计算，缺少可用驾驶座、发动机、变速箱或油箱时禁止使用装配。可以购买、升级、维修实例或解锁底盘；资源不足时档案不变。升级至 L 级消耗 50L 货币 / 10L 废料，最高 5 级；每级火力或发动机动力 +5%。

已安装不代表可用：耐久 0 的部件已毁坏，仍占格并保留质量，但功能失效。驾驶提示会区分“缺少可用部件”和“已安装但已毁坏”；工作台图上红叉表示毁坏，黄色叹号表示半血及以下受损，仓库与选中说明显示实际耐久和状态。营地无法驾驶时点击“车辆无法驾驶 · 拖车维修”，依次选中毁坏的发动机/驾驶座，再点击“维修 20 / 5”（每件 20 货币、5 废料）。维修即时入档，直接关闭工作台即可更新营地和准备页驾驶条件；草稿布局只有“保存并使用”才会成为当前装配。

填名称后“保存方案”新建独立方案；选中方案后加载或删除。“保存并使用”把当前装配存为出击装配，刷新仍可恢复。“还原出厂布局”只重排已有库存，缺失件不会补造。副本内没有改装入口。

战斗左下显示原装配布局的纸娃娃：绿色正常，黄色闪烁为半血以下降效，红叉为毁坏失效，虚线缺口为外露件脱落，并有可读状态说明。减少动态效果系统设置会关闭闪烁。右上小地图保留，中央驾驶视线净空。

射界投影于地面。所有武器提示经过共同的 1.5 倍车体包围半径净空裁切，并添加一逻辑步移动余量；近距离准星隐去。装填和热量弧位于射界外沿，不在车顶堆叠状态条。伤害按目标/类型/0.2 秒窗聚合，最多 24 条，0.8 秒回收，净空内不显示；显示聚合不改变结算。

九种武器在装配和战斗中使用同一独立矢量设计，车上直接显示基座、炮管、枪口或撞角。炮台的活动部分按真实瞄准角旋转，有限射界与转速来自武器配置；地面射界内的细线显示当前炮口方向。净空裁切只作用于提示，车上的武器本体正常可见。

敌人按车辆、步兵和建筑绘制：可见车轮/车窗、头盔/四肢或混凝土射孔，分别带真实挂载武器与血条。双方开火都有枪口焰、按武器区分的弹丸与拖尾、命中火星及爆炸；突刺/反应装甲使用接触或爆炸反馈。战斗页面不显示试车场练习标签。

新增 `combat-presentation.spec.ts` 验证炮台旋转与指向细线像素、三种竖屏真实交火和绘制无副作用。证据为 `battle-320/390/430.png` 与相应状态JSON，设计总览为 `weapon-enemy-designs.png`，均位于原UI证据目录。

营地装备界面打开时清除驾驶输入并暂停车辆，保存并使用后立即更新营地车辆，关闭后需驶离停车区再返回才会再次打开。结算页在保存成功前禁用返回营地，失败显示重试入口。IndexedDB 保存仍以唯一 runId 保证幂等。

验证：`npx playwright test tests/e2e/vehicle-ui.spec.ts`；320、390、430 像素竖屏证据见 `openspec/changes/add-vehicle-ui/evidence/`，包含网格编辑、真实存档重载、失败重试和净空像素检查。真机手感与压测继续在原待办中单独验收。
