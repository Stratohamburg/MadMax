# Design

## Context

动机和范围见 [proposal.md](proposal.md)，行为合同见 [vehicle-physics](specs/vehicle-physics/spec.md)。当前为 TypeScript／Vite／Canvas 2D 客户端，1/120 秒外层时钟与时间标记输入已实现。`model.ts` 直接增加 heading、夹目标角并让 motion 指数追赶；`config.ts` 的 baseline-1 无轴距、轮胎或车型配置；碰撞只清标量速度，绘制和胎痕各自计算轮位，回放覆盖固定证据路径。

此前 `validate-driving-prototype` 的轴动力规划未实施。本变更将其核心规则迁至单独的 vehicle-physics，原 vehicle-handling 保留输入接入合同，driving-playground 保留场景、画面、碰撞、车型选择和手机验收。本变更可以脱离场景实施；原变更随后接入，避免循环依赖。现有README／运行说明中残留的axle-dynamics-1目标版本须在对应文档同步任务中归并为本规范，保留baseline-1运行事实，不维护两个升级目标。

用户确认摇杆始终表示期望路线方向，漂移允许车头偏向弯内。十类车为游戏调校原型，不是实际品牌或车型的测量标定；卡车和重卡首版均为刚性车身及前后等效轴。

## Goals / Non-Goals

**Goals:**

- 一套求解器，以成组参数区分十类车型，能从基准证据解释差异。
- 前轮、轮胎、轴距、载荷和惯量形成真实运动；路线、车头与侧滑可分别观察和控制。
- 汇总研究中尚未采用的方向，区分本次必做、可关闭机制和后续扩展。
- 参数有单位、版本、关联约束和调校顺序，物理、辅助、游戏代价分别可查。

**Non-Goals:**

- 首版不做逐轮轮速、差速器、完整多轴／挂车、悬挂／侧倾、外倾与方向机自然回正。
- 不以型号标签写不同物理算法，也不允许每种车独立使用一个重力。
- 不实现购买、解锁、库存、载货流程或正式车型美术；运行中载荷变化另立变更。

## Decisions

### 1. 核心边界与版本

物理核心只接受状态、配置、Intent、路面采样和 dt。浏览器、时钟驱动、相机、碰撞求交、面板和绘制属于消费者。核心导出创建／推进／观测／完整重置／碰撞停车／几何／配置校验接口，可在无 DOM 环境运行。

采用 `modelVersion=vehicle-physics-1`、`profileSchemaVersion=vehicle-profile-1`，每预设有 profileId、profileRevision；全局规则、路面及基准也记录版本。旧 baseline-1 拒绝导入。axle-dynamics-1 是被取代的未实施规划，不当成曾经发布的配置迁移。证据入口由运行方指定，核心不写验证场目录。

拟拆 `geometry`、`loads`、`tires`、`powertrain`、`steering`、`dynamics`、`profiles`、`benchmarks` 职责；相邻小文件可合并，但各层可独立验证。model 保留公共门面，不保留旧角度追赶链路作为第二套生产模型。

### 2. 坐标、单位和权威状态

屏幕 +x 右、+y 下、正角顺时针。车体前向 f=(cos(theta),sin(theta))，右向 s=(-sin(theta),cos(theta))。前轮右转、横摆顺时针为正。

全部车型共用世界长度 L、质量 M、秒 T 的尺度。可令参考车质量为一，但所有车必须相对同一质量单位；初始参考车长1.2、轴距0.84、Vmax12、gGame9.81仅沿用为游戏调校起点，不称真实米／公斤标定。若改到SI，须对全局尺度和全部参数一次性换算，不逐车混用。

权威状态：位置、worldVelocity、theta、横摆 r、实际前轮 delta、漂移混合 h、轮胎瞬态状态、上次物理纵向作用、辅助目标／参考历史。deltaTarget、betaTarget、速度、运动方向为输出或派生量，不能被测试接口分别任意覆写：

```text
u = dot(worldVelocity,f); v = dot(worldVelocity,s)
V = length(worldVelocity)
beta = atan2(v,u)
chi = theta + beta = atan2(worldVelocity.y,worldVelocity.x)
chiDot = cross(worldVelocity,worldAcceleration)/V^2
betaDot = chiDot-r
```

零速时chi仅以theta显示，动态分支不用除零表达式。重置、换车和测试初态工厂须一致构造全部状态，专用固定前轮／纯模型入口仅用于验证。

派生字段只读：lf/lr、Iz、静态轴载荷、动力重量比、低速理论半径、参考欠转特性、有效μ。只编辑L与质心比例，不让lf/lr/L三份值独立矛盾；只编辑kYaw或Iz之一。

质量不是独立的“笨重系数”：若m、Iz、力和刚度同比放大，几何不变时响应可能基本相同。重车差异必须结合更低Fdrive/m、更长L、更大的kYaw、更慢前轮、更窄稳定包络等形成。该缩放性质单独测试。

### 4. 几何与低速

L=lf+lr，轴在车身内，质心与绘制中心可以有偏移，前后悬及车宽定义占地。输出前后轴、四轮接地点、前后车身边界和保守占地轮廓；长车不能只导出质心小圆。

```text
frontLeft  = position+lf*f-track/2*s
frontRight = position+lf*f+track/2*s
rearLeft   = position-lr*f-track/2*s
rearRight  = position-lr*f+track/2*s
Rrear = L/tan(delta)
betaKin = atan(lr/L*tan(delta))
rKin = V*cos(betaKin)/L*tan(delta)
```

低速前轮显示可由等效delta派生阿克曼内外角：非零转角时|Rrear|已知，内／外角为atan(L/(|Rrear|∓track/2))，按转弯方向分配左右并加符号。参数须保证最大角下分母为正；直行直接返回零。动力学用等效delta，不宣称已求四轮力；大侧滑不强制四轮同心。

低速采用运动学，正常速度用动力学，在lowSpeedStart/End间smoothstep混合导数。低速分支以有限响应收敛到betaKin/rKin，并包含转角变化对运动方向的影响；跨区不重置速度方向和姿态。正常几何betaKin不属于轮胎打滑。

### 5. 动力、制动与纵向载荷转移

保留非线性曲线的语义，但以真实作用力为配置源：

```text
FdriveMax(V)=Fdrive0/(1+ka*(V/Vmax)^2)
FbrakeMax(V)=Fbrake0*(1+kb*(V/Vmax)^2)
A(V)=FdriveMax(V)/m; B(V)=FbrakeMax(V)/m
```

速度请求增量先限制到不跨目标，再形成力请求；驱动／制动分配到前后轴，经过抓地预算才成为实际力。Vmax为车型实际速度上界，通过动力请求及有界候选增量处理，不每步把速度赋成摇杆目标。滚阻和可选风阻独立计算，稳态动力可前馈补偿，不能将同一阻力既放进曲线又重复扣除。目标零时用不跨零耗散有限停车；任意正目标不能因阈值失效。

纵向准静态载荷使用物理纵向作用估计aLong，不直接用含转向投影或游戏扣速的speed差分：

```text
deltaFz=m*aLong*hCG/L
FzF=m*gGame*lr/L-deltaFz
FzR=m*gGame*lf/L+deltaFz
```

首版使用上一固定子步物理作用估计形成因果更新，初态为零；在子步收敛测试中验证该近似。轴载荷非负、总量m*gGame守恒；超限须限制相应物理请求并记录介入，默认预设不靠常态夹载荷运行。运行中载货与俯仰运动不在首版。

### 6. 轮胎曲线、组合预算与瞬态

```text
alphaF=atan2(v+lf*r,u)-delta
alphaR=atan2(v-lr*r,u)
```

每轴用自身Fz、路面和轮胎适应计算μxPeak／μyPeak；可选载荷敏感度围绕固定标称轴载荷调整μ和刚度，默认零可退化为常系数。全局上限及跨字段校验保证合法。首版只含前后载荷变化，不把这个系数宣称为左右载荷转移或侧翻。

以小角刚度、峰值和形状派生峰位，避免四项任意配置互相冲突。一个可选C1曲线起点：设Fpeak=μyPeak*Fz、形状a∈(0,3]，alphaPeak=a*Fpeak/CAlpha，z=|alpha|/alphaPeak；z≤1使用Fpeak*[a*z+(3-2a)*z²+(a-2)*z³]，z>1使用Fslide+(Fpeak-Fslide)*exp(-((|alpha|-alphaPeak)/falloffWidth)²)，方向阻碍侧滑。Fslide≤Fpeak；两者相等时退化为峰后平台。该曲线为游戏近似，非直接复刻Pacejka。

纵向请求先夹到FxCap，侧向纯轮胎曲线再乘sqrt(max(1-(Fx/FxCap)²,0))，形成抓地椭圆；FxCap=0时直接返回相应零能力。前后轴独立预算，驱动份额不等于额外牵引加成。首版没有κ或轮速，不能把后轴降低包络称为精确动力空转。

轮胎瞬态是独立可关闭机制，σ=0直接准静态。非零时按τ≈σ/max(transportSpeed,vReg)的有界响应推进一致的轮胎状态，禁止任意依赖渲染帧的插值。轮胎瞬态与执行器delta响应、横摆r、漂移h分别观测。

瞬态模型须明确储能／耗散或采用有被动性依据的离散方式，不能仅滤波力值便声称物理正确。低速转运动学时连续衰减相关状态；路面／载荷预算下降后，投影瞬态作用到新包络并记录耗散，不能用历史力越界。无驱动验证机械能加必要轮胎储能无持续增益；准静态反向测试检查力阻碍实际接地点侧滑。

实施先让σ=0通过受力、能量、反打基准，再开启单轴／双轴瞬态通过相同基准与子步收敛，最后决定各预设非零初值。机制必须交付，值由调校确定，不能以恒为零冒充瞬态已验证。

### 7. 世界受力与横摆

```text
FxBody=FxF*cos(delta)-FyF*sin(delta)+FxR
FyBody=FxF*sin(delta)+FyF*cos(delta)+FyR
worldAcceleration=(FxBody*f+FyBody*s)/m + dissipativeTerms
yawAcceleration=(lf*(FxF*sin(delta)+FyF*cos(delta))-lr*FyR)/Iz
positionDot=worldVelocity; thetaDot=r
```

世界速度为权威，避免遗漏或重复车体科里奥利项。轮胎作用经力矩推进r，不能到目标角就清零。无辅助测试几何、左右符号、惯量和耗散后再调控制，防止辅助掩盖错误受力。

### 8. 路线、侧滑和自动反打

摇杆角度是chiTarget，不是delta或thetaTarget。普通目标最终对齐路线与车头，漂移允许车头提前指向弯内；精确180°沿最近有效路线转向参考，无历史用固定方向，不强制实际r方向。

先根据预测路线误差生成受速度／抓地限制的chiDotRef。正常转弯的betaSteady从低速几何和中高速稳态模型／标定取得，不能全速沿用betaKin。漂移增加有界betaDriftExtra，方向与入弯甩尾相符：

```text
betaRef=bounded(betaSteady(V,chiDotRef,loads,grip)+h*betaDriftExtra)
betaDotRef=rateLimitedResponse(betaRef-beta)
rRef=chiDotRef-betaDotRef
deltaFF≈atan(L*rRef/max(u,uMin))+dynamicSteadyCorrection
deltaTarget=clamp(deltaFF+Kbeta*(beta-betaRef)-Kr*(r-rRef),±deltaMax(V))
```

上述为游戏控制起点，增益按V、有效抓地和h连续调度；不能把rRef直接写入r。预测、参考、前轮执行均限速，无积分积累。普通小侧偏动态修正可用欠转标定；大侧滑采用有界反馈和实际力预算，不把线性公式外推成保证。

前轮与有限动力请求共同满足路线和姿态稳定；合法受力及稳定优先，Vmax仍是请求，不承诺急转时实际速度不掉。目标侧滑随速度和转弯需求连续变化，直线无需求时为零；h控制进入／恢复，退出保留所有动态，逐步减小betaDriftExtra并增强稳定反馈。

无有效方向时不追旧路线，以侧滑／横摆稳定和回正为目标并减速停车。持续漂移用预设转弯需求或时间标记路线序列验证，不能把恒定世界目标角当作恒定圆周曲率。

### 9. 游戏代价与尺度校准

继续按chiTarget与theta的最短夹角算额外代价：q=clamp((|error|-freeAngle)/(90°-freeAngle),0,1)，loss=lambdaMode*V*q^p。无目标q=0，漂移lambda更大。此项沿速度反向耗散、与轮胎物理／滚阻分开，不改运动方向。漂移持续保有车头偏角也承担同样代价，辅助不豁免。

调校先核对aLat/V、V²/(μgGame)及V²/(gGame*L)量级。参考初值Vmax12、μ0.95、gGame9.81时理想稳态最小半径约15.5世界单位，驱动占预算时更大；场地若太紧，统一调整速度／尺度／全局抓地环境或场地，不逐车偷偷改g。

### 10. 路面和车型预设

核心从前／后轴接地点采样surfaceId、μ比例和滚阻，轮胎配置再提供该路面族的适应系数。首版三类基准为干硬路、松散地、湿滑低抓地；默认采样显式返回干硬路。物理不导入验证场world；测试可提供分段路面采样函数。过边界按各轴实际采样更新预算，状态连续；本阶段不做左右轮split-μ。

车身宽／长、前后悬、质心高、轮胎、制动与转向并非都用同一缩放。每个完整预设要填写所有字段和验收窗口，表仅指导调校；最终值由下述基准冻结。首版不热插载货，未来空载／满载可先作为独立静态配置，再考虑运行时质量及质心变化。

### 11. 数值、保护和生命周期

外层1/120秒，每外步固定两次1/240秒中点RK2子步，输入外步采样，执行器／h／轮胎状态在子步推进。不可按渲染自适应步数。瞬态刚度采用稳定离散或可验证闭式更新，必须通过1/480对照；非法参数组合由配置校验拒绝。

靠近侧滑软边界时增强稳定、收紧路线参考和动力。极端候选违反前进约束时限制旧状态到候选增量，不能直接夹运动角；介入记录次数和强度。正常、持续漂移、反打基准硬保护为零。

重置清速度、r、delta、h、轮胎／载荷／辅助历史；碰撞停车还清会释放旧力的瞬态，完全阻挡的姿态撤回由场景完成。后台物理冻结，输入和时钟积压由接入层清理，恢复不复活旧目标。

### 12. 车型基准和通过标准

先纯物理、再相同公共辅助、最后各车调校辅助，报告明确三者。公共速度定义为待比较两车较小Vmax的35%；另做各车25/50/75% Vmax的归一化测试。提速与制动使用相同绝对速度段；不能给重车更低速度就声称制动更好。

| 指标族 | 测量方式 |
| --- | --- |
| 直线动力 | 从0到公共速度时间，低／高速加速能力，必要时单列最高速度 |
| 制动 | 从公共速度到零时间与距离，不能把时间和距离当两个不同指标族 |
| 几何 | 固定相同实际前轮角的低速半径、前后轴轨迹、占地尺度 |
| 转向瞬态 | 公共速度30°路线阶跃的10–90%响应时间、横摆建立 |
| 稳定性 | 超调、稳定时间、残余侧滑／横摆／前轮，持续1秒正速度窗口 |
| 漂移 | 标准转弯需求下侧滑峰值／持续窗口、反打时刻、恢复衰减 |
| 路面适应 | 同公共速度与输入在三路面的路径误差、速度保持与抓地占用变化 |

相近七对由spec列明，每对至少两个不同指标族差异≥15%，相对差=|a-b|/max(|a|,|b|,epsilon)；近零指标不用该比值冒充差异，换用有意义非零指标并注明。类别间方向性来自配方目标，不宣称真实世界普遍排名。不得只按最高速度区分，不要求45个任意车对都满足同一排序。

默认跑车普通3秒／反打4秒及0.8秒反轮门槛见spec。其余预设初始普通／恢复稳定窗口上限为：轻皮卡3.5/4.5秒、重皮卡4/5秒、van4/5秒、厢货4.5/5.5秒、卡车5/6秒、重卡6/7秒、拉力3/4秒、肌肉3.5/4.5秒、越野4/5秒。这些是待验证门槛；相同角度误差与1秒正速度保持继续适用，各车漂移初态按合法侧滑／速度包络定义并在调校前冻结。无法通过要记录失败和原因；变更验收窗口须更新规划及证据，不能测试后静默放宽。

共同检查：几何比例≤3%；载荷和预算守恒；左右镜像；无驱动能量；瞬态开关；默认硬保护零；十车型10秒30/60/120FPS回放容差为车长1%、Vmax0.5%、各方向及前轮0.5°、横摆0.5°/秒；1/240与1/480子步5秒位置差≤车长5%、车头≤2°。残余量和角差均用绝对值。

持续漂移采用默认跑车与拉力车各自合法的非零转弯需求场景，须有至少1秒、|beta|≥5°且速度≥对应目标60%的窗口，路线误差绝对值≤10°、实际侧滑与参考差≤8°，左右镜像、无硬保护；直线需求归零后恢复。该场景不要求重卡复制跑车的漂移角。

## Risks / Trade-offs

- [质量被同比缩放抵消] → 检查F/m、Iz/(mL²)与几何等指标，至少两个指标族证明差异。
- [辅助把所有车修成一样] → 先无辅助／公共辅助测量，再调车型增益，冻结差异报告。
- [路线／侧滑同时追赶引发振荡] → 有界参考、稳态前馈、速度／抓地调度、正速度稳定验收。
- [轮胎瞬态或峰后曲线放大数值问题] → 准静态基线、可关闭机制、能量与子步收敛、严格参数组合。
- [重车物理升级但碰撞仍是小圆] → 核心提供占地，接入变更必须完成长车平移／旋转扫掠验收。
- [大侧滑目标一直增加游戏代价] → 明确沿用规则，联合调动力、预算和目标角，不能隐藏豁免。
- [游戏尺度被误认为实车标定] → 标注统一游戏单位及未验证初值，保留全局尺度检查和来源边界。

## Migration Plan

1. 先修订两个变更归属，保留旧acceptance和证据；新核心只依赖公共数学／类型，不导入验证场。
2. 先在独立模块提供新配置、状态和几何，以一个默认跑车及准静态轮胎通过受力、载荷、能量和低速测试；尚未切换的baseline客户端只作历史运行入口，不用新配置驱动它。公共model门面和生产消费者在接入变更一次性切换并移除旧算法，核心测试与构建无需依赖尚未实施的场景改造。
3. 接路线／侧滑辅助、反打与代价，随后开启峰后及轮胎瞬态，建立稳定默认。
4. 填十车型完整配置与三路面，执行公共基准和各车包络，冻结版本与差异证据。
5. 原验证场接所有公共消费者、车型选择、长车碰撞和完整生命周期，复跑浏览器与手机；核心无需等待手机才能完成自己的独立验收。
6. 文档随各自实施任务同步；回退时成套回退核心配置／状态／消费者，不把baseline-1配置注入新核心。当前无用户车辆存档迁移需求。
