# Design

## Context

副本模式是系统整合层，不重复实现战斗、改装或加成，只负责流程、关卡与规则编排。

## Decisions

- **状态机**：副本用显式状态机（准备/局内/结束/结算），转移纯函数化，便于测试与回放。
- **关卡数据驱动**：关卡定义为数据（区域、刷新表、搜刮表、撤离点、Boss），可播种。
- **掉落/携带**：携带空间按格子或重量其一，首版采用物品格数；与局外仓库的容量独立。
- **失败损失**：按配置比例对装配逐件判定，使用可播种 PRNG，保证结算可复现。
- **叙事**：仅提供节点事件与解锁钩子，不实现剧情内容。
- **PVP 预留**：局内核心逻辑不依赖本地单机假设（确定性、固定步长、输入序列），但本期不做网络。

## Risks / Trade-offs

- 搜打撤的损失规则影响留存，需经过试玩调整，规则做成配置。
- 与现有"验证场"并存：保留练习场入口作为独立场景。

## Implementation Decisions

- 示例关卡“废弃货场”沿用练习场世界边界与碰撞体，准备页选择装配后显式 enter/start；局内固定 1/120 秒，上限 180 秒，8 格携带。
- 刷新、搜刮和失败损失使用独立种子流；每件战利品以 runId 派生唯一 ID。波次满池时排队重试，不消耗刷新项。
- 南出口 20 秒开放；北出口要求 Boss 死亡。圆形范围内自动计时 5 秒，离开即归零；首次撤离结束整局，Boss 未死也可南撤。
- 失败丢弃携带物，并按原装配实例排序逐件以 25% 概率损失。外露脱落件无论胜负均损失；未脱落内部损伤交给结算保留。
- 拾取和升级节点靠近自动触发；满载保留地面物品并提示。3、8、15 击杀及区域节点给三选一，选择时暂停模拟；Boss 击杀且成功撤离才触发主线解锁。
- 模块护甲先吸收玩家受击，损毁派生新装配；动力链、资源、后坐力、碰撞、被动事件、维修区和邻接修饰符全部接入同一 session。缓存组合结果，仅损伤/升级变化时重算。
- 终局状态深冻结；结算包含原装配、存活耐久、带出物、损失、主线事件和统计，后续持久化按 runId 原子应用。独立练习场保留现有调试接口。

## Physics Integration Revision

每步先消费健康/装配/升级变化，并将旧机械状态及刚体经核心迁移到新参数；再推进驾驶、场景碰撞、有限质量敌人运动与实体冲量，刷新玩家查询位置后生成实际运动事件及开火/后坐力，最后战斗/维修/结算。死亡实体不参与接触，伤害冷却不停止物理响应，接触伤害与撞击伤害有独立来源。
