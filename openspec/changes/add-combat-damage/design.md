# Design

## Context

目标是手机 Canvas 2D 上的大量弹丸。性能风险最高，需最先做原型压测；渲染方案本期不动。

## Decisions

- **数据布局**：弹丸与敌人使用固定容量的结构数组（SoA）与对象池，避免逐帧分配。
- **空间索引**：均匀网格/空间哈希，供武器射程查询与弹丸碰撞共用。
- **倍率栈共享**：flat / 加算 / 乘算三层与 `add-assembly-physics` 共用同一实现，避免两套规则。
- **聚合策略**：弹丸饱和时合并相近同类弹丸为"聚合弹丸"，伤害累加，保证总输出不变。
- **输出给渲染**：只输出位置、类型与聚合后的伤害数字事件，渲染不反向影响战斗。
- **固定步长**：战斗在外层 1/120 秒时钟内推进，与物理同序，保证可回放。
- **随机数**：可播种 PRNG，种子写入战斗状态。

## Risks / Trade-offs

- 手机帧率预算未知：先出压测再定容量与聚合阈值。
- 聚合弹丸会让体感略有差异，需在设计评审中确认可接受。

## Implementation Contract

- 默认预算为 2048 弹丸、128 敌人（另有玩家槽），核心固定步 1/120 秒，压测报告 p50/p95/max，目标 p95 ≤ 4 ms。该值为待真机验证的工程目标，不是已通过的移动端结论。
- 2026-11-01 用户确认暂无法连接手机，授权先实施其余工作；真机压测独立为未完成任务，保留设备/系统/浏览器/热机时长/数量/统计的记录入口。
- 敌人与弹丸使用固定容量 typed arrays，空间哈希复用桶。敌人满载时延后刷新，不销毁既有敌人；AI 提供有限速度追击与有冷却的接触攻击，供 PvE 示例波次使用。
- 伤害类型为 physical/explosive/fire。共享分层属性在暴击前求值，抗性限制为 0～0.9，护甲按 `100/(100+armor)` 减免，最终伤害不小于零；返回每层结果。死亡后不再进入目标查询，死亡事件只发一次。
- 弹丸使用线段扫掠避免高速穿透，命中顺序按线段参数和稳定实体 ID 排序；已命中 ID 集合避免穿透弹跨步重复伤害。爆炸对每个范围目标一次结算，直击目标不重复承受额外直击。
- 容量包含按阵营×伤害类型保留的 6 个聚合槽（容量最少 6）；普通槽耗尽后使用本组保留槽，再按同阵营同类型的最近弹丸合并，累加伤害和数量，保留累计输出账本。聚合会近似轨迹，报告聚合次数；不丢弃原始伤害载荷。
- 燃烧为有时限的周期伤害，同来源刷新时长，多来源最多 8 层；制导弹丸按有限转速追踪仍存活的锁定目标，失去目标沿当前方向飞行。
- 模块按 HP>50% Normal、0<HP≤50% Damaged、HP=0 Destroyed 分类。装配派生消费健康比例；外露件归零从装配移除，内部毁坏件保留质量；油箱毁坏发出起火事件，电池毁坏撤去供电。
- 来袭方向覆盖范围内的外层装甲/外挂先承伤，再到内装甲和车体；方向由挂点 facing 确定。部件变化后重新 compose，保留未脱落部件的耐久和运行时资源。
- 机械师占内层格，仅自动修复非零耐久部件，不复活 Destroyed；维修区可以将零耐久的仍在车上部件先恢复到50%，快速修复其余部件并补满当前容量内弹药。脱落件不能凭空生成。
- 战斗只输出聚合伤害数字和状态事件，绘制不能改变结算；同种子输入的状态与事件逐步一致。压力脚本支持无头 Node 与浏览器入口，结果标注是否真实移动设备。

## Enemy Roster Revision

敌人配置包括类型、血量、护甲、半径、质量、速度/加速度、停止距离、接触攻击和武器挂载。步兵含步枪兵/火箭兵，车辆含机枪皮卡/装甲机炮车，建筑含机枪碉堡/火箭塔，首领为重炮装甲车。敌方使用同一有限转速、射界、发射和命中管线，固定建筑质量为静态且不追击。步兵在真实法向撞击速度达到1.2时可被撞死，车辆同时受冲量派生伤害；伤害冷却不阻断真实接触处理。具体数值统一由目录维护。

## Physics Integration Revision

有限质量圆形敌人持有实际平移速度与质量，追击用有限加速度请求接近玩家，受撞击后仍连续运动；接触攻击保持独立冷却。实体接触调用 vehicle-physics 的车身边界/圆形接触，不使用车身保守圆作为真实形状。核心返回法向速度、冲量、耗散及双方新速度；PVE 仅在阈值和冷却满足时计算撞击伤害。冷却只控制伤害，不控制冲量。装配脱落统一调用核心质量迁移，不能只替换 profile。

## Architecture Revision

性能边界：v5 将敌车接入完整车辆物理后，128 敌人（54 辆车）与 2048 弹丸容量的桌面压力记录为 p95=14.7717ms，超过原 4ms 工程目标及 120Hz 单步预算。报告保存在装配变更的 v5 证据目录，`withinEngineeringTarget:false`；旧版轻量敌车压力结果只作历史。已消除重复车型复制、实体查找和无冲量时的状态重建，后续需继续优化批量状态及接触候选；真机性能验收仍未完成。

敌方 vehicle 类型以独立车辆运行状态推进，与玩家共用装配驾驶入口；AI只产生世界运动方向与目标速度。车辆间接触使用双刚体求解，物理结果同步到实体池只读投影。步兵保留有限加速度移动，建筑保持静止。敌车开火后坐力也由同一物理入口处理；死亡清理对应运行状态。
