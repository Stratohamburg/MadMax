# Design

## Context

动机与范围见 [proposal.md](proposal.md)。当前项目只有 README、OpenSpec 配置与技能，没有游戏源码、构建配置或既有能力规范。本变更新建第一阶段浏览器驾驶验证场。

已确认的关键约束是：单摇杆的任意非零位移同时给出速度与方向输入，车辆静止时不原地旋转；漂移包含真实侧滑，车头与实际运动方向短暂分离；普通满油门与漂移之间有独立外拉行程；转向减速由目标方向与车头的夹角决定。

本文中的技术栈、公式形式与起始参数是本阶段采用的设计默认值，参数需要通过驾驶验证调整，不代表已经完成手感测试。

第一阶段体验闭环为“进入验证场 → 驾驶直道与不同弯道 → 观察速度和侧滑 → 重置或调参 → 再次验证”。后续冒险挑战建立在已经验证的驾驶规则上。

## Goals / Non-Goals

**Goals:**

- 将输入、车辆运动和绘制分离，使同一套物理状态既能由手机触控驱动，也能在无画面的测试中回放。
- 明确定义三种方向及其关系，避免将侧滑做成只有拖尾的视觉效果。
- 将规则不变量与调校参数分开，让更换车辆参数不改变输入语义和验收标准。
- 使阈值、速度曲线、转向曲线和速度损失可以被单独观测，再通过同场驾驶评估组合手感。

**Non-Goals:**

- 不做轮胎受力、悬挂、档位或真实发动机模拟；以可预测的街机式驾驶为目标。
- 不引入通用场景编辑器、完整实体组件框架、联网同步或动态刚体碰撞。
- 不把调试数据堆入普通驾驶界面；参数和方向向量仅在显式开启的验证模式中显示。

## Decisions

### 1. 使用 TypeScript、Vite 与 Canvas 2D，物理逻辑独立运行

采用 Canvas 2D 绘制场地、车辆和拖尾，以普通网页元素承载摇杆、HUD 和验证面板。Pointer Events 统一处理触摸与鼠标，Vitest 用于确定性物理测试，Playwright 用于浏览器布局与输入生命周期检查。

选择轻量方案是因为当前只需要一个静态场地和一辆车，便于直接检查操控公式。Phaser 等完整游戏框架可在后续场景规模扩大时重新评估，本阶段不承担其场景与物理体系的接入成本。

建议的职责分界为输入采样、车辆参数与运动、场地与碰撞、镜头与绘制、验证工具；源码目录在实施时按这些边界组织，不要求提前建立完整游戏架构。

```text
Pointer Events --> Joystick Intent --> Fixed Physics --> Vehicle State
                         |                  |                 |
                         v                  v                 v
                   Input Feedback      Static Collision   Canvas View
                                            |
                                            v
                                      Test Observation
```

### 2. 固定视图方向，按完整漂移圆适配摇杆

主视图默认占可见视口高度 60%，操控区占其余空间，HUD 与重置入口位于主视图内。布局依据动态可见视口计算，操控区扣除安全区和内边距后，为完整外圈保留圆形空间。

设扣除内边距后的操控区尺寸为 Wc、Hc：漂移进入半径 Renter 不大于 min(Wc, Hc)/2，正常满油门半径 R = Renter/1.4，退出半径 Rexit = 1.2R。这样满油门缓冲行程为 0.4R，进入退出滞回宽度为 0.2R；比例是起始调校值。

采用固定中心摇杆，镜头只跟随位置、不随车头旋转。目标方向直接对应屏幕方向。暂不增加随速度变化的镜头缩放或前视偏移，先减少手感比较的变量。

摇杆使用真实触点距离计算输入；视觉拇指可以限制在外圈显示，但不能将计算距离截断到正常满油门半径。输入区域处理 touch-action，活跃触点捕获后继续跟踪越界拖动。额外触点不能抢占。

尺寸变化、触点结束、取消、捕获丢失和页面隐藏均清除输入。重置后需重新触碰，不复用仍然按下的旧触点。

### 3. 采用目标车速语义，严格保留任意非零位移

摇杆提供距离 r 与目标角度 alpha。正常满油门半径为 R：

```text
throttle = clamp(r / R, 0, 1)
targetSpeed = Vmax * throttle
```

只有 r = 0 或输入已结束时，速度输入才为零，此时没有有效方向目标。没有 r0、中心死区或微小正速度截断。数值误差处理只能用于夹住减速越过零的结果，不能抹掉合法正输入。

这里把“油门深度”落实为玩家请求的目标速度比例。车辆实际速度还受加减速、转向损失与碰撞影响，因此满油门不保证车辆始终达到 Vmax。

### 4. 非线性加减速与按速度变化的转向率

以世界单位和秒描述物理量。设当前速度 v，u = clamp(v/Vmax, 0, 1)：

```text
A(v) = A0 / (1 + ka * u^2)
B(v) = B0 * (1 + kb * u^2)

vDrive = moveToward(v, targetSpeed, A(v) * dt)  if v < targetSpeed
vDrive = moveToward(v, targetSpeed, B(v) * dt)  if v > targetSpeed
vDrive = v                                         otherwise
```

moveToward 在目标处夹断，不越过目标。A0、B0、ka、kb 均为正值，因此加减速度确实随当前速度变化；B0 保证低速减速也能在有限时间内到零。

两种模式 m 分别使用转向率曲线：

```text
g(v) = v / (v + Vs)
Omega_m(v) = Omega0_m * g(v) / (1 + k_m * u^2)
```

g(0) = 0，使零速时没有转向能力，起步后平滑获得转向能力；高速部分的分母降低转向率。普通与漂移分别配置 Omega0_m、k_m，不能只改拖尾而共用相同转向行为。

方向差归一化到最短角弧，每步转角限制在目标差值以内。精确 180°沿上一次有效转向符号，没有历史值时默认顺时针；不对相邻的非 180°输入增加额外方向死区。

### 5. 用独立运动方向产生实际侧滑

定义 alpha 为摇杆目标、theta 为车头、psi 为实际运动方向。角度统一使用弧度存储，界面和验收可换算成度。

车头以对应模式的 Omega_m(v) 追赶 alpha。运动方向通过抓地响应追赶车头：

```text
followWeight = 1 - exp(-grip_m(v) * dt)
psiNext = psi + shortestAngle(thetaNext - psi) * followWeight
velocity = vNext * direction(psiNext)
```

普通模式使用较高抓地响应；漂移使用较低抓地响应，使车头先改变而位移方向稍后跟上。漂移抓地在低速区向普通值平滑靠拢，vBlend 默认为 0.3Vmax；完全静止时可以让内部 psi 收敛到 theta，theta 保持不动。

所有模式共用小于 90°的最大侧滑角，起始值 65°。当跟随结果超过该上限时将偏差限制在上限，确保运动沿车头方向始终有正分量；退出漂移时不把该上限突然收紧到零。

退出漂移仅切换抓地响应和转向曲线，保留已有 theta、psi 和速度，不直接令 psi = theta。指数跟随保持运动方向连续，避免轨迹在切换瞬间突变。

### 6. 使用意图夹角计算转向代价

在每个物理步开始时，用该步输入和原车头得到 delta = abs(shortestAngle(alpha - theta))；没有有效方向输入时强度为零。设免损角 deltaFree 小于 90°：

```text
q = clamp((delta - deltaFree) / (90deg - deltaFree), 0, 1)
turnLoss = lambda_m * v * q^p
vNext = clamp(vDrive - turnLoss * dt, 0, Vmax)
```

lambda_drift > lambda_normal > 0，p 起始取 2。相同速度与非零 q 下漂移减速更大，delta 达到 90°后不再加重。deltaFree 是方向夹角的免损区，与摇杆中心死区是两件不同的事，不影响任意非零位移产生速度。

先进行有目标夹断的动力更新，再扣转向损失，避免直接把实际速度赋成目标速度而消除过弯代价。验证面板同时显示动力贡献和转向损失，便于解释满油门仍掉速的原因。

一次物理步的顺序为：采样输入与漂移状态、计算旧状态下的意图夹角、更新速度、按更新后的正速度限制转向、跟随运动方向、求位移与静态碰撞、提交状态及拖尾。动力与转向损失更新后的速度为零时不计算转向；如果之后碰撞完全阻挡位移，则同时撤回本步车头变化。静止输入会先获得正速度并产生行驶过程，不存在独立的原地转向阶段。

### 7. 用固定时间步和连续接触处理稳定驾驶结果

物理步长采用 1/120 秒，渲染由 requestAnimationFrame 驱动并在相邻物理状态间插值。输入事件按时间戳采样，物理步使用对应时刻的最新输入；角度插值使用最短角弧。

页面隐藏时暂停模拟、清除输入并丢弃累计时间，重新显示时重建时间基准；前台异常长帧最多处理 100ms 的积压，其余丢弃，避免恢复后跨越场地。正常 30、60、120 FPS 条件下不丢步。

静态碰撞使用圆形近似车身与矩形障碍、封闭边界。检查本步扫掠路径以阻止穿透；接触法向阻止穿入，允许可通行的切向位移，碰撞完成后速度归零且不反弹。若候选运动被完全阻挡、没有有效位移，则不提交本步车头变化，保持“不能靠撞墙原地转头”。接触面存在切向空间时，新的输入可通过起步、微小转向和切向移动脱离；死角另提供重置恢复。

第一阶段不做冲量、摩擦材质或碰撞伤害。采用完整刚体物理虽然能覆盖更多碰撞姿态，但会使第一阶段难以单独判断摇杆与转向公式的表现。

### 8. 初始调校集中配置，变更参数后重置比较

下列数值仅为第一轮可运行基线，允许在保持规范不变量的前提下调整：

| 参数 | 起始值 | 单位或用途 |
| --- | --- | --- |
| Vmax | 12 | 世界单位/秒 |
| 车身长度 / 碰撞圆半径 | 1.2 / 0.45 | 世界单位 |
| A0 / B0 | 6 / 8 | 世界单位/秒² |
| ka / kb | 2 / 1 | 加减速曲线系数 |
| Vs | 0.8 | 低速转向过渡速度 |
| Omega0_normal / Omega0_drift | 3 / 5 | 弧度/秒 |
| k_normal / k_drift | 1.4 / 0.8 | 转向随速度变化的系数 |
| grip_normal / grip_drift | 12 / 4 | 每秒响应系数，漂移低速时向普通值靠拢 |
| lambda_normal / lambda_drift | 0.18 / 0.45 | 每秒速度损失系数 |
| deltaFree / p | 5° / 2 | 小角度免损与损失曲线指数 |
| 最大侧滑角 | 65° | 全模式共用上限 |
| Rexit / Renter | 1.2R / 1.4R | 漂移退出与进入半径 |

验证面板仅在显式验证模式启用，允许修改这些参数；应用时校验合法范围并重置车辆。非法值保留原配置并显示原因，尤其保证最高速度大于零、加减速能力为正、漂移损失大于普通、漂移抓地小于普通，以及半径顺序成立。

参数变更后统一重置，避免将车辆运行中的突变误判为驾驶规则问题。第一阶段只维护一套默认测试车，不增加车型选择流程。

### 9. 场景、镜头与拖尾服务于可重复观察

场地由静态几何图形构成，明确标识直道、缓弯、急弯和连续弯，并在开放区放置少量实体障碍。镜头保留足够范围观察转弯轨迹，初始可见世界高度取约 16 个世界单位，再根据手机体验调校。

普通驾驶 HUD 提供当前速度、漂移状态和重置入口。验证模式额外显示 alpha、theta、psi 三个方向向量、速度目标、意图夹角、损失强度与转向减速贡献。

拖尾按轮胎世界位置采样，避免将渲染帧数作为生成数量依据；以正速度和实际侧滑角控制可见强度。退出漂移后仍有明显侧滑时允许短暂延续，再随侧滑减弱消退。直线切入漂移不强制造出强烈胎痕。历史拖尾设置寿命和容量上限，重置时清空。

### 10. 以行为测试和真实驾驶共同验收

行为合同见三份 [能力规范](specs/)。自动测试重点验证可观测性质与跨时间输入结果，不为公式逐行复制一套同构计算。

| 验证项 | 方法 | 通过条件 |
| --- | --- | --- |
| 任意非零输入 | 测试中心、微小位移、R/2、R、Renter | 精确中心为零；所有测试中的非零位移都有正速度与方向；R/2 为半速目标 |
| 非线性速度控制 | 无转向场景下比较低速与高速区间、减小目标、松手停车 | 加减速随速度变化；不越过目标；有限时间停稳 |
| 静止不转头 | 零输入静止保持、侧向输入起步、完全阻挡运动 | 没有独立的原地旋转，起步与转向伴随可执行位移 |
| 漂移分区与滞回 | 逐段外拉、进入后小幅回收，再收至退出阈值 | 缓冲区可保持普通满油门；边界不抖档；入漂不增加油门上限 |
| 实际侧滑与退出 | 同速比较普通与漂移路径，并记录退出前后角度 | 漂移 theta 与 psi 可区分；位置与 psi 连续；退出后逐步恢复 |
| 转向损失 | 固定原始状态比较免损角、45°、90°、120°、180°及两种模式 | 小角度零损失；90°封顶；同条件漂移损失更大 |
| 方向边界 | 179°到 -179°、精确 180°重复输入 | 走短弧；正后方选择稳定 |
| 帧率一致性 | 无碰撞场景按相同时间轴回放 10 秒输入，分别以 30/60/120 FPS 渲染 | 位置差 ≤ 车身长 1%；速度差 ≤ Vmax 的 0.5%；两种朝向差 ≤ 0.5° |
| 触控与布局 | Playwright 检查三种规范尺寸及安全区；验证越界、第二触点、中断、隐藏恢复 | 比例与全向行程成立；无页面滚动；不残留旧输入 |
| 碰撞、拖尾与重置 | 最高速度碰撞、可通行接触面脱离、长时间漂移、漂移中重置 | 不穿透或倒车弹射；拖尾有上限；重置恢复完整状态 |
| 手机驾驶手感 | 至少一台真实手机浏览器人工驾驶，记录型号、系统与浏览器版本 | 能有意保持普通满油门、连续进出漂移、细微保速修正及完成连续弯，记录误触与不适 |

按时间标记的 10 秒输入覆盖半速直行、满速直行、普通转向、漂移、退出和松手。测试输入直接注入物理时钟，避免把浏览器事件投递时间误差混入物理一致性测试；触控路径由独立浏览器检查覆盖。

实施阶段在该变更目录补充验收记录，明确每项“通过、失败、未执行”、使用的参数版本与待解决事项。自动化通过与手机实测通过分别记录；没有实机证据时，第一阶段整体验收保持未完成。

## Risks / Trade-offs

- [零中心死区可能接收手指细微抖动] → 保持用户确认的非零输入规则，通过低速转向曲线和清晰回中反馈控制体验，不偷偷添加吞输入阈值。
- [小屏幕下外拉距离不足或误触] → 按完整漂移圆计算布局，以半径比例保留缓冲和滞回，并在三种小屏尺寸与实机上检查所有方向。
- [降低抓地可能导致车头转过但路线长期不跟随] → 同时调校漂移转向率、抓地曲线和侧滑上限，用 theta、psi 与轨迹一起评估。
- [按意图夹角减速会让突然反向掉速明显] → 保留规则，用小角度免损和可调损失指数提供精细保速空间，验证面板展示原因。
- [前进限制与静态碰撞可能在封闭死角造成无法驶离] → 接触允许切向位移，开放练习区域保留足够空间，并始终提供重置；本阶段不扩展倒车机制。
- [数学测试不能证明手机上好操作] → 将实机驾驶作为独立验收项，记录未解决问题，调校后再回归相关性质测试。

## Migration Plan

本项目没有既有客户端或线上用户数据需要迁移。实施先建立本地开发与静态构建入口，再依次接入物理、输入和验证场；构建产物可由静态站点托管，本阶段不要求发布到公网。

默认参数作为独立配置保留；调校异常时可恢复上一套参数并重置场景。若未来替换渲染框架，保留输入与车辆行为合同及回放测试，避免更换框架时隐式改变手感。
