# Proposal

## Why

现有模型直接修改车头、再让运动方向追赶，不能体现前轮、轴距、轮胎受力与反打；此前规划仍以单辆测试车为中心。项目将有轻／重型皮卡、van、厢式货车、卡车、重型卡车、跑车、拉力赛车、肌肉车和越野车，需要独立、统一且可验证的车辆物理能力，保证车型差异来自成组参数和实际运动。

## What Changes

- 单开 `vehicle-physics` spec，统一管理车辆几何、前后轴力、横摆惯性、低速过渡、控制辅助、车型配置和调校验收；现有 `vehicle-handling` 改为输入到物理的接入合同，验证场继续负责场景、画面、碰撞和手机体验。
- 保留非线性加减速、前进约束、静止车身不旋转、外拉漂移满油门，以及免损角／90°封顶／漂移更大的额外速度代价。
- 明确摇杆始终表达世界中的期望路线方向；普通行驶最终同时对齐车头与路线，漂移允许车头偏向弯内，自动控制前轮、侧滑与横摆，退出连续反打回正。
- 采用低速运动学与中高速非线性单轨动力学；增加简化纵向载荷转移、峰值到滑动区的轮胎曲线、纵横抓地预算，以及可关闭且可验证的轮胎瞬态。
- 建立几何／质量与惯量／动力制动／轮胎与路面／转向／漂移／辅助／游戏代价参数组，分离全局物理规则、车型数据和路面数据；十类车型共用求解器，禁止按类别名称硬编码轨迹。
- 提供十类数据预设与可重复对比基准，测量提速、制动、转弯半径、横摆响应、超调、侧滑与恢复、跨路面保持等指标；相近类别也须有多维差异。
- 首版卡车与重卡为刚性单车身、前后等效轴；建立路面抓地与滚阻采样入口，采用三个基准路面验证轮胎适应性。轮速／纵向滑移率、差速器、完整多轴与挂车、横向载荷转移、悬挂／侧倾、外倾与自然回正力矩列为后续扩展。
- **BREAKING**：权威状态改为速度向量、横摆、前轮、漂移／轮胎瞬态等；使用 `vehicle-physics-1` 模型及 `vehicle-profile-1` 配置格式，拒绝 `baseline-1` 及被本提案取代、尚未实施的 `axle-dynamics-1` 参数格式。
- 允许必要重构，建立纯物理测试入口、统一几何与配置生命周期；与验证场共同迁移所有消费者和证据版本，不保留两套权威物理。

## Capabilities

### New Capabilities

- `vehicle-physics`：不依赖浏览器界面的平面车辆物理、路线意图辅助、可差异化车型参数、轮胎／路面响应及确定性调校基准。

### Modified Capabilities

无已归档能力，`openspec/specs/` 为空，使用 ADDED Requirements。同步修订在途变更 `validate-driving-prototype` 的既有规划，将其物理内部规则归并到本 spec，保留原能力路径作为接入／场景合同，不另造同义物理能力。

## Impact

- 重构 `src/vehicle/model.ts`、`config.ts`，按职责建立几何、轮胎、载荷、动力积分、路线辅助、车型配置及基准模块；沿用 TypeScript、Vite、Canvas 2D、Vitest、Playwright 和固定外层时钟。
- 核心提供真实轮胎位置、前轮状态、占地几何和完整观测；`validate-driving-prototype` 接入渲染、长车碰撞、胎痕、调参、车型切换、后台与重置，依赖本核心，不实现第二套模型。
- 新证据记录模型、配置格式、车型／配置修订、路面、控制器和场景版本；保留旧验收与回放，量化门槛是待验证目标。
- 本变更不依赖验证场的运行时模块，可先独立实施与验证；验证场随后消费公共接口，两个变更各自满足验收后再归档。车辆购买、解锁、库存、正式美术与冒险内容不在本次范围。
