# Design

## Context

后期爽感来自倍率叠加，同时数值易失控。分层规则需在一处实现并由车辆、武器、伤害共用。

## Decisions

- **单一属性求值器**：`evaluate(base, modifiers, tagContext)`，被 compose、武器和伤害管线调用。
- **标签集合**：目标自带标签集合，修饰符以"全含/任一"匹配；标签表集中维护。
- **协同**：基于装配相邻图预计算，装配变化时增量更新。
- **候选生成**：加权无放回抽样，权重 = 基础权重 × 稀有度系数 × build 标签倾向；保底计数器随局内状态保存，使用可播种 PRNG。
- **诊断工具**：无头 CLI，输入装配+加成，输出属性贡献表与估算 DPS，用于数值平衡与回归。
- **局内范围**：加成状态属于一局，随局结束丢弃；仅结算时的掉落进入局外。

## Risks / Trade-offs

- 乘算层过多会爆炸：设置乘算来源分组（同组乘算合并）并提供诊断阈值。
- 标签设计需与内容同步演进，首版限制标签数量。

## Open Questions

- 稀有度档位数量与保底阈值（待平衡）。
- PVP 中倍率是否封顶（本期不做 PVP，仅预留）。
