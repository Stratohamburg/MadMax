# 战斗、损伤与维修

`CombatWorld` 以 1/120 秒固定步推进。实体和弹丸采用 typed arrays 固定容量池，空间哈希复用桶；实体死亡只发一次事件，之后从索敌与碰撞中移除。敌人以有限速度追击玩家，贴近攻击冷却为 0.75 秒。

## 伤害与弹道

伤害顺序为共享 flat/increased/more → 暴击 → 抗性 → 护甲。抗性限制为 0～0.9，护甲倍率为 100/(100+armor)，最终伤害不小于零。`calculateDamage` 返回每层贡献，武器事件在生成弹丸时固定进攻侧倍率与暴击，命中时应用目标防御。

高速弹丸按每步位移线段扫掠。穿透记录已命中实体，避免同一弹丸跨步重复命中；爆炸对每个范围目标一次结算，不叠加直击。制导受有限转速限制，目标丢失后直飞。燃烧按来源刷新持续时间，最多8个来源，固定步结算。

扫掠按圆形目标的实际入射点排序。满池合并穿透弹时，为每个目标保留已结算伤害额度；后续合并仅补结新增载荷，既不因旧命中集合吞掉新增伤害，也不重复应用旧伤害。

默认最多2048弹丸、128敌人及一个玩家槽。弹丸容量最少6，包含阵营×伤害类型的6个保留槽。普通槽耗尽后使用本组保留槽，继续溢出时将同阵营同伤害类型载荷并入最近弹丸，累加伤害和数量；`aggregated` 与 `emittedDamage` 记录聚合与载荷账本。聚合近似轨迹和命中时间，因此高负载时视觉/目标分配可能变化；同类型累计伤害载荷不丢弃。敌人满池时刷新方保留待刷新项。

## 模块与驾驶

耐久 >50% 为 Normal，0<耐久≤50% 为 Damaged，归零为 Destroyed。装配健康比例由 `moduleComposition` 传给 compose：发动机受损功率减半、变速箱换挡时间加倍、电池最大输出减半；武器层处理射速减半与散布加倍。

`damageByDirection` 根据挂点朝向选择覆盖方向的外层件，再到内装甲，余量作用于车体并损伤内部件。外露部件毁坏后脱落、质量与功能移除；内部毁坏件保留质量。油箱毁坏记录起火事件，电池毁坏移除供电。`damageModule` 可以供精确部件命中使用。

弹药箱毁坏后移除其可用容量；副本同步截断剩余弹药、电量和燃料至当前有效容量。模块与升级变化时重算装配和邻接修饰符，普通步复用缓存。

机械师占用内层格并缓慢修复非零耐久件，不能复活 Destroyed。维修区快速修复；仍安装的零耐久件先恢复到50%，下一步才继续维修。`serviceVehicle` 同时按当前装配容量补满弹药。已脱落部件不在装配中，维修不会凭空生成。

## 压测与设备边界

```powershell
npm run combat:benchmark
npx vitest run tests/unit/combat.test.ts
```

浏览器/手机打开 `/?combat-benchmark=1` 点击压测按钮。预热120步，测量600步，记录实际峰值弹丸数、敌人数、p50/p95/max单步耗时及聚合数量。工程目标为2048/128、p95≤4ms；结果的 `mobileVerified=false` 不会因 UA 看似移动设备而自动修改。

本机结果保存在 `openspec/changes/add-combat-damage/evidence/desktop-benchmark.json`。真机验收还需设备型号、系统、浏览器版本、热机时长和测试报告；用户于2026-11-01确认当前无法连接手机，因此此任务保持未完成，其余工作继续。
