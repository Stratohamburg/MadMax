# Design

## Context

战斗需与固定步长物理同步，且需支持数百弹丸的"天女散花"场景。武器逻辑应与渲染分离并确定性运行。

## Decisions

- **触发策略接口**：每种武器类型实现 `canFire(context) -> FireDecision`，四类触发（炮台/固定/制导/被动）各为一种策略，由数据中的 `trigger` 字段选择，新增类型不改核心循环。
- **世界/局部变换**：挂点与朝向取自装配清单，每步用车体位姿换算到世界坐标。
- **目标查询**：通过空间哈希提供射程/扇形查询；查询接口在 `add-combat-damage` 中提供，本变更定义接口并用测试替身验证。
- **制导进度**：每武器单独维护进度计时器，状态可序列化以便回放。
- **确定性**：不使用 `Math.random`，随机散布使用可播种 PRNG，种子进入战斗状态。
- **后坐力**：开火产生外力事件，由 `build-vehicle-physics` 的核心外力接口消费。

## Risks / Trade-offs

- 弹丸数量大时的开销在 `add-combat-damage` 中以对象池处理；本变更只产出开火事件。
- 目标选择规则过多会增加平衡难度，首版提供 3 种规则。

## Implementation Contract

- 武器状态按装配 instanceId 索引；移除/毁坏后移除该武器状态。目标 ID 为稳定整数，所有目标规则最终按 ID 升序决胜；武器按 instanceId 代码点排序消耗共享供给。
- 坐标由 compose 的质心相对挂点变换至世界；八方向 facing 作为基准角，炮台有限转速和转角限制独立于车头。炮台对准误差不超过 0.04 rad 才开火；固定/制导武器只查询其扇形，射程与扇形边界包含在内。
- 制导保持同一目标才累积，切换目标归零；离开时按数据选择 reset 或 decay。开火后重置锁定。
- 所有武器使用整车共用能源与分类型弹药，不设置管路。供电不足通过有限充能降低有效射速；无电池输出时停火，剩余电量不足只能使用已充入的能量。单发耗能为额定功率/基础射速，弹药不足不部分发射。
- 每步更新冷却/散热，过热达到上限后停火，降到恢复阈值才解除。高射速可在一个固定步发出多次事件，不能按渲染帧数触发。
- 被动事件固定为 hit/collision/kill/drift/speed/boost，带递增 sequence、来源和 magnitude；每件武器记录最后消费序号并设置内置冷却，生成事件不能在同一步递归订阅自身。
- xorshift32 的整数状态进入武器状态，零种子映射为固定非零值；散布每颗弹丸单独取样，恢复后继续相同序列。
- FireEvent 携带每颗弹丸的方向、速度、伤害、范围效果、穿透及状态效果；后坐力独立为世界挂点冲量，交由物理接口结算。
- 展示数据包含基准/瞄准角、射界/射程、车身中心 1.5 倍保守半径净空、装填外沿进度、过热和锁定进度；DOM/Canvas 不参与目标、冷却或开火判定。
- 受损武器射速减半、散布加倍，毁坏武器停火；运行时倍率经共享属性求值器计算，原始定义保持不变。

## Weapon Presentation Revision

- 九种武器各有独立矢量轮廓、枪口距离、弹丸样式、拖尾和命中样式；装配 SVG 与战斗 Canvas 共用设计数据。
- 炮台基座跟随车体，转动部分消费实际 aimAngle；机枪全周、加农炮270°、机炮180°射界，分别配置转速。导弹发射架保持基准朝向，制导弹丸独立转向。
- 实际发射原点取真实枪口，射界从挂点基座计算；指向细线显示当前炮口方向，所有提示仍按1.5倍车身半径裁切，武器本体不受提示净空裁切。
- 开火、命中、爆炸事件带稳定序号和模拟时间，展示事件最多512条，绘制特效最多256个，按事件时间回收，不参与伤害和随机序列。

## Motion Event Revision

后坐力外力合同归 vehicle-physics，装配仅提供一致挂点。drift 事件由实际速度≥1 game-L/s 且绝对侧滑≥5°产生，magnitude 表示实际持续秒数；与漂移辅助请求无关。speed 表示实际质心速度，boost 事件依据该步实际助推输出，collision 依据核心接触冲量，不把控制意图伪装成结果。

## Architecture Revision

武器接收本步分配到的功率额度，按稳定实例顺序为每件武器有限充能；充能从共享电池扣除并计入本步总输出，射击消耗本地充能和弹药。充能上限为单发耗能，初始为零；失去供电时不发射电力武器。后坐力通过统一外部冲量批次提交，包含模拟步、来源和单调序号。
