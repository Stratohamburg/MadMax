# Proposal

## Why

本项目的核心体验取决于单摇杆能否同时提供细腻的速度控制、可预期的转向和主动触发的侧滑漂移。目前项目只有 OpenSpec 工作流结构，需要先以可在手机浏览器运行的驾驶验证场验证这些规则，再展开冒险内容。

## What Changes

- 整理车辆冒险游戏大纲，明确移动端竖屏、2D 俯视角、车辆第三人称控制，以及驾驶系统与后续冒险内容的边界。
- 建立竖屏驾驶界面：上方游戏主视图至少占可见视口的 60%，下方提供全向虚拟摇杆，并容纳漂移外拉行程。
- 将摇杆任意非零位移同时映射为正的目标速度和目标方向；只有精确回中或输入结束时目标速度为零，不设置吞掉微小速度输入的中心死区。
- 实现随当前速度变化的加减速、普通转向率和漂移转向率；车辆保持前进，静止时不原地旋转。
- 在普通满油门半径之外保留满油门缓冲行程，继续向外拉才进入漂移；进入与退出阈值分离，漂移档保持最大油门。
- 分别计算车头朝向和运动方向，使漂移产生实际侧滑，并在退出时平滑恢复抓地；转向减速由摇杆目标与车头夹角决定，小角度免损、90°及以上封顶，同等条件下漂移损失更大。
- 提供一个含直道、缓弯、急弯、连续弯及少量静态障碍的驾驶验证场、一辆参数可配置的测试车、漂移拖尾、重置入口和仅用于验证的观测工具。
- 第一阶段交付以驾驶可控性与移动浏览器体验为验收目标；地图冒险流程、战斗、任务、车辆获取成长、账号、联网和正式美术不在本阶段范围内。

## Capabilities

### New Capabilities

- `mobile-driving-interface`：竖屏视图比例、单摇杆速度与方向输入、漂移外拉分区、状态反馈及触控生命周期。
- `vehicle-handling`：前进行驶、非线性加减速、随速度变化的转向、实际侧滑漂移与按意图夹角计算的转向速度衰减。
- `driving-playground`：用于反复验证操控的驾驶场景、跟随镜头、静态障碍、漂移拖尾、重置与验证观测。

### Modified Capabilities

无。当前项目没有既有能力规范。

## Impact

- 目标项目为当前 MadMax 目录；尚无游戏源码、前端构建配置或既有运行时需要兼容，第一阶段将新建浏览器客户端。
- 技术方案建议采用 TypeScript、Vite 与 Canvas 2D；使用浏览器 Pointer Events 和本地静态资源，无后端服务依赖。
- 物理行为与渲染分离，车辆参数集中配置，为后续增加车型和冒险内容提供基础。
- 验证采用确定性操控测试、浏览器布局与触控检查，以及手机实机驾驶评估；本次仅创建规划文档，不包含功能实现或已通过实机验证的声明。
